# 聚合视频 v1.2.0 —— Android 与 macOS 发布（Linux 延后至 v1.2.1）

> **本次发布的正式产物只有两个平台**：**Android**（APK）与 **macOS**（arm64 DMG）。

---

## 一、为什么本次只发 Android 与 macOS？（如实说明）

我们把"能跑"与"敢发布"分得很清楚，本版按后者执行：

| 平台 | 本次是否发布 | 原因 |
|---|---|---|
| **Android** | ✅ 发布 | 已通过**真机**完整验收：安装、启动、搜索、播放、下载、本地库、字幕、主题跟随。本版还修掉了一个**真机可复现的崩溃**（见下）。 |
| **macOS** | ✅ 发布 | 已通过本机多轮实测：SPM 构建、DMG 打包、播放、字幕、音频兜底、主题跟随全部走通。 |
| **Linux**（Arch / Debian / Fedora） | 🚧 **本次不发布** | 打包链路已打通（Arch `PKGBUILD`、Debian `dpkg-buildpackage`、Fedora `mock` + Copr 均已实际出包），但：<br>① 三发行版之间**功能与打包方式尚未统一**；<br>② 若干优化（真实 GPU 下的渲染后端验证、长时续航等）**尚未完成**；<br>③ 按既定决策，Linux 端将**统一实现、统一打包**后随 **v1.2.1** 发布。<br>**我们不愿意把一个"能编译但不保证各处一致"的 Linux 版本当作正式版推给用户。** |

> Fedora 用户可在 **Copr 测试渠道**提前体验（`sudo dnf copr enable houge/hov-qt`），
> 但请务必理解为**实验性、可能不稳定**，正式支持见 v1.2.1。

## 二、本版亮点

### 一、崩溃与卡死根治（本版最重要）

- **Android：默认渲染后端导致的原生崩溃（本版核心修复）** ★
  实测发现：mpv-android 的默认 `vo=gpu` 在部分机型（测试机 Xiaomi 17 Pro Max / Android 16）上
  **在 `vo` 线程内原生崩溃**（tombstone 栈在 `libmpv.so`，可 2/2 复现），
  而 **`vo=gpu-next`（libplacebo）稳定可用**（三轮复现 + PSNR 与 mpv 帧号双重佐证）。
  → 本版 Android **固定采用 `gpu-next`**，设置项中不再提供开关（避免用户误选到会崩的路径）；
  同时**不读取历史设置**，以免老版本遗留的 `false` 值把用户带回崩溃路径。
- **macOS：下载落盘卡主线程 1.9 秒** —— 文件删除/移动原先在主线程执行；
  改为放到 URLSession 回调（本就在后台队列），主线程只留状态更新。
- **三端：退出时偶发 SEGV** —— 数据源 model 信号原以 `this` 为接收者，析构顺序不定导致悬空调用；
  改为**以被访问对象为接收者**（Qt 侧：谁被槽访问，谁当接收者）。
- **Linux（本版未发布，一并说明）**：中文环境启动段错误（libmpv 要求 `LC_NUMERIC=C`，且校验发生在
  动态库加载阶段）→ 由**启动器脚本**在 exec 前修正；长时间播放后 `abort`（libmpv 的 GL fence 泄漏）
  → 在 `get_proc_address` 处包装 `glFenceSync/glDeleteSync` 记账兜底。

### 二、主题跟随系统（新增）

- 三端统一设置项 `ui.theme = auto | dark | light`（默认 `auto`）；
- **Android**：`isSystemInDarkTheme()` + Compose 状态桥，切换即时生效；
- **macOS**：`ThemeController` 单点真相（darkAqua / aqua 实测确认）；
- Linux 走 XDG Desktop Portal（本版未发布）。

### 三、字幕

- **默认显示改为"按系统语言自动选轨"**：按系统语言提示给字幕轨打分（精确匹配 > 同语族 > 中文简繁 > 英文兜底），
  只有匹配到才自动开启 —— 而不是无脑打开第一条；
- **字幕字号**统一为画面高度的 2.8%（下限 13px），三端一致；
- macOS 侧修复了三处各自写 karaoke 标记导致的顺序 bug（收敛为单一写入口）。

### 四、音频可靠性（macOS）

- **纯音频兜底**：当选中档位只有视频流（`acodec==none`）时，自动改用 `bestAudioOnlyUrl`；
- **音轨看门狗**：10 秒无音轨提示、15 秒无音频数据则自动换轨；
- 全部字段写入 `[AUDIO]` 日志，便于排查。

### 五、搜索与界面

- **搜索结果无限下拉**：每页 20 条、无开关、页数上限 YouTube 6 页 / 其它 5 页、
  按"多取后截尾"翻页、URL 去重、会话代次防竞态；滚动到距底 200px 自动加载；
- **卡片视图**：完整缩略图（fit，不裁切）+ 标题两行 + 来源标签，真·masonry 排布；
- **状态信息不再污染结果区**（独立状态行）；
- **结果区尺寸**启动固定为「横向 2 张 × 纵向 4 张」，拖动分隔条后记住。

### 六、播放可靠性（三端）

- **直链过期自愈**：记录解析时刻 + 按来源 TTL（YouTube 4h / B站 2h / 音乐 30min），
  过期或进度停滞 15 秒时自动重新解析并**回到原位置**（每条内容最多自愈一次）；
- **后台属性快照**：主线程读 mpv 属性会拿核心锁，网络 demux 期间易冻结 →
  改为后台线程 5Hz 快照，GUI 只读快照；
- **缓存按来源区分**：网络 `cache=yes / 60s / 64MiB`；本地 `cache=no / 4s / 8MiB`（本地大缓存会导致拖动冻结）。

### 七、下载

- **视频不再"没有声音"**：`bv*+ba` 拆成两路时原先只下第一路 →
  现为视频下完后并行下载音轨（带 Referer/UA）→ ffmpeg 本地混流（`-c copy`）→ 清理临时文件；
- 音乐下载带封面 + `.lrc` 侧车；视频任务一律跳过音乐标签嵌入；B站/YouTube 下载补 Referer。

## 四、已知问题（如实）

1. **Linux 端**：功能与打包仍在统一中，**本版不发布**；Copr 渠道为实验性、可能不稳定。
2. **Linux 侧三处文件 I/O 仍在主线程**（LRU 清理、混流替换、入队删旧文件），与 macOS 同类问题；
   Linux 上未观测到卡顿，已记录待改，随 v1.2.1 处理。
3. **Linux Flatpak / AppImage 暂缓**（AppImage 打包链路在安装布局变更后需修复）。
4. **非致命日志问题**：直链自愈在"直链来自上次会话恢复"时会打印一个无意义的极大秒数
   （内部把绝对时间戳当成了已过时长）。**仅影响日志可读性，不影响自愈行为**，计划在 v1.2.1 修正。
5. **YouTube 字幕 429 / 机房 IP 风控**属网络环境问题，非应用缺陷；VM 内 B 站 412 同理。
6. macOS 应用**未做公证（notarization）**，首次运行需在「隐私与安全性」中手动允许。

## 五、升级说明

- 三端共用配置：`~/.config/hov/settings.json`、`queue.json`、播放进度与本地库均为**覆盖安装不丢数据**；
- **Android**：从 v1.1.0 升级直接安装覆盖即可；若此前装的是 debug 版再装 release 版会因**签名不同**失败，
  需先卸载（debug 与 release 签名不可混装，这是 Android 的机制，不是应用缺陷）；
- **macOS**：首次运行如被拦截，见「系统设置 → 隐私与安全性 → 仍要打开」。
